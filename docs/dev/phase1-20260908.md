## 1. 무엇이 바뀌었나 (Task 1–5)

| Task | 무엇 | 결과물 판 |
|---|---|---|
| 1 | KAM 항목 경계 교정. 「핵심감사사항이 없다」 선언문은 `preamble`, 계속기업 불확실성 안내는 `going_concern_notice` 로 갈라 `kam` 행에서 뺐다. | `kam-v2` |
| 2 | 감사의견 **축 분리**. 재무제표 의견(`audit_opinion`)과 내부회계관리제도 의견(`icfr_opinion`)을 구역으로 나눠 따로 뽑고, 확정 여부(`opinion_status`)·출처(`opinion_source`)·감사보고서 수(`audit_report_count`)를 남긴다. | `af-v2` |
| 3 | 계속기업 기재 **위치·시점**(`gc_material_uncertainty`·`gc_location`), 강조/기타사항 **상태**(`emphasis_status`·`other_matter_status`). 랜드마크를 표제 자리로 한정해 구역 과확장을 없애고, 어미 안에 낀 공백(「있습니 다」)을 정규화했다. 다른 감사보고서 의견을 옮겨 적은 문장은 계속기업 기재로 세지 않는다. | `af-v2` |
| 4 | 기준서 조기적용 판정. 근거를 **회사가 주어인 문장**으로 옮기고, 「검토 중」=미적용, 시행일만 적힌 기준서 설명문=`PERMITTED_ONLY`, 신규 적용 목록의 기준서=`ADOPTED`(신규 값). 목록 서문 귀속을 절(section) 안으로 가뒀다. | `ps-v2` |
| 5 | 측정모형 판정. 손상 **조건절**을 재평가로 읽지 않고, 유형자산은 자산군(토지/건물/그 밖)별 행을 따로 내며 회사 수준 행은 값이 갈리면 `MIXED`. 「일부 수익은 진행기준」=`BOTH`. 투자부동산은 블록 간 값이 갈리면 `UNDETERMINED`+`CONFLICT`(어휘에 조합값이 없다). 절 번호+표제가 본문에 붙은 수익인식 블록을 새로 인식한다. | `ps-v2` |

## 3. 실행 명령과 소요 시간 (2026-09-08)

산출물 폴더: `/mnt/raid/ruci_workspace/dart-collector-out/phase1-20260908/`
원문·매니페스트: `dart-search-mcp/dart_collected/{manifest.json,docs/}` (읽기 전용)

```bash
OUT=/mnt/raid/ruci_workspace/dart-collector-out/phase1-20260908
DC=/mnt/raid/ruci_workspace/repo/mcp/dart-search-mcp/dart_collected

# ① 감사 메타 — 8분 01초 (16:10:50 → 16:18:51)
uv run dart extract-audit-facts --manifest $DC/manifest.json --docs-dir $DC/docs \
  -o $OUT/audit_facts.jsonl --summary $OUT/audit_facts.jsonl.summary.json \
  --checkpoint $OUT/audit_facts.jsonl.checkpoint.json

# ② KAM 분할 — 1초 (LLM·네트워크 없음)
uv run dart split-kam --facts $OUT/audit_facts.jsonl -o $OUT/kam_items.jsonl

# ③ 회계정책 — 15분 41초 (16:29:43 → 16:45:24), 규칙 6분 + LLM 9분
uv run dart extract-policy-stances --facts $OUT/audit_facts.jsonl --docs $DC/docs \
  -o $OUT/policy_stance.jsonl --llm --llm-workers 8 --llm-subjects 1109,1113,1116,1117,1118

# ④ 게이트 / 차등 / 회귀
uv run dart policy-stance-gate --stances $OUT/policy_stance.jsonl -o $OUT/gate.md
uv run python scripts/phase1_diff.py $DC $OUT
uv run python scripts/phase1_regression.py $OUT --check-versions
```

| 단계 | 입력 | 출력 | 소요 |
|---|---|---|---|
| 감사 메타 | 48,537 공시 | 47,477행 (실패 1,060 = XML 없음, ps-v1 과 같은 수) | 8분 01초 |
| KAM | 47,477행 | 2,791 공시 → 3,185 항목 | 1초 |
| 회계정책 | 47,477행 · 47,477 보고서 | 141,975행 (LLM 492회, 실패 0) | 15분 41초 |

**`--llm-subjects` 를 붙인 이유(브리프 명령과의 차이).** 브리프의 ③ 은 `--llm --llm-workers 8` 만
쓴다. 그대로 띄워 규칙 통과까지 돌린 결과 LLM 대기 열쇠가 **54,860건**이었다(PPE 35,792 ·
REVENUE 9,919 · STD 5,118 · IP 4,031). 게이트웨이 단건 왕복 실측 2.5초를 8 워커로 나누면
약 **4.8시간**이라 중단하고, 비교 대상인 옛 산출물(`ps-v1`)이 쓴 것과 같은
`--llm-subjects 1109,1113,1116,1117,1118` 로 다시 돌렸다(492회, 9분). 이렇게 하면 차등이
「ps-v2 규칙의 효과」로만 읽힌다 — LLM 범위까지 같이 넓혔다면 두 변화가 섞인다.
중단한 실행의 규칙 통과분은 `policy_stance.rules.jsonl` 로 남겨 뒀다(최종본과 규칙 부분이 같다).
subject 없는 주제(PPE·REVENUE·IP)를 LLM 으로 판정하려면 별도 실행이 필요하다 — 남은 최대
후보는 1115호(보류 1,627건)다.

## 6. temis-backend 인계 절차

1. 산출물 3개를 그대로 복사한다(`temis-backend/data/dart_mvp/`).

   ```bash
   OUT=/mnt/raid/ruci_workspace/dart-collector-out/phase1-20260908
   cp $OUT/audit_facts.jsonl $OUT/kam_items.jsonl $OUT/policy_stance.jsonl \
      <finov2>/temis-backend/data/dart_mvp/
   ```

2. 적재는 temis 쪽 스크립트로 한다(이 저장소에는 적재기가 없다).

   ```bash
   cd <finov2>/temis-backend
   .venv/bin/python scripts/import_dart_mvp.py --data-dir data/dart_mvp
   ```

   `import_dart_mvp.py` 는 `--data-dir` 안에서 `corp_master.csv`·`audit_facts.jsonl`·
   `kam_items.jsonl` 을 찾는다. `corp_master.csv` 는 이번 재추출과 무관하므로 기존 것을 그대로 둔다.

3. **새 열은 적재 코드가 무시한다.** temis 적재기는 자기가 아는 열만 읽으므로 `opinion_status`·
   `icfr_opinion`·`gc_material_uncertainty`·`gc_location`·`emphasis_status`·`sentence_kind`·
   `held_reason` 같은 열이 늘어도 적재는 그대로 성공한다. 반대로 말하면 **새 열을 화면에 쓰려면
   temis 쪽에 읽는 코드를 따로 넣어야 한다** — 이번 인계만으로는 화면이 달라지지 않는다.

4. **`ADOPTED` 는 temis·FE 양쪽에서 네 군데를 고쳐야 한다.** ps-v2 가 새로 내는 값이라 기존
   어휘 상수에 없다. 네 군데 중 **둘은 표시(라벨)일 뿐이지만 둘은 기능 관문**이다 —
   기능 쪽을 빼먹으면 값이 DB 에는 3,251행 들어가 있는데 **조용히 조회되지 않는다**(오류도 안 난다).

   | 종류 | 위치 | 빼먹으면 |
   |---|---|---|
   | **기능** | `_POLICY_TOPIC_VALID_VALUES["STD_EARLY_ADOPTION"]` — `.wt-notes-be/app/services/dart_agent/tools.py:84-87` | `tools.py:864` 가 `policy_value=ADOPTED` 를 `ignored_filters` 에 넣고 「모르는 정책 값이라 무시했습니다」로 넘긴다. 필터가 **통째로 사라져** 걸러지지 않은 전체 집합이 답으로 나간다 |
   | **기능** | FE `POLICY_VALUES.STD_EARLY_ADOPTION` — `policyVocabulary.ts:49` | 조건 패널이 `ADOPTED` 를 **선택지로 내놓지 않는다** — 사용자가 그 값을 고를 방법 자체가 없다 |
   | 표시 | temis-backend `_POLICY_VALUE_LABELS` | 화면에 코드 문자열(`ADOPTED`)이 그대로 보인다 |
   | 표시 | FE `policyVocabulary.ts` 의 라벨 맵 | 같음(빈칸 또는 코드 문자열) |

   `policyVocabulary.ts` 는 **`temis-frontend` 본체가 아니라** 정책 축 작업 트리
   (`.wt-notes-fe` / `.wt-policy-fe`)의 `src/components/dart/policyVocabulary.ts` 에 있다.

5. **KAM 은 적재 전에 kam-v1 행을 지워야 한다.** `import_dart_kam_items` 는 upsert 가 아니라
   **삽입 전용이고, 이미 있는 키는 건너뛴다** — 적재 시작 때 `(rcept_no, seq)` 집합을 통째로 읽어
   두고(`temis-backend/app/services/dart_mvp_import.py:222`) 그 집합에 있는 키는 `continue`
   한다(`:230-231`). `kam-v2` 는 항목 경계 자체를 바꿔 같은 `(rcept_no, seq)` 에 **다른 본문**이
   오는데(선언문·계속기업 안내가 `kam` 에서 빠지고, 한 항목이 둘로 갈리거나 둘이 하나로 합쳐진다),
   그 키들은 「이미 있다」고 건너뛰므로 **kam-v2 본문이 아예 들어가지 않는다**. 새로 생긴 키만
   들어가서 옛 본문과 새 본문이 섞인 표가 된다. 그래서 upsert 로도, 그냥 재적재로도 안 되고
   **kam-v1 행을 지우고 새로 넣어야** 한다(행의 `splitter_version` 으로 판을 구분할 수 있다).

6. **`policy_stance.jsonl` 은 소비 브랜치(`.wt-notes-be`)의 `import_dart_mvp.py` 가 직접 읽는다**
   — `scripts/import_dart_mvp.py:86` 이 `data_dir / "policy_stance.jsonl"` 을 입력으로 잡고,
   `import_dart_policy_stances`(`app/services/dart_mvp_import.py:338`)가
   **`(rcept_no, topic, subject_key)` 로 upsert** 한 뒤 그 파일에 실린 `rcept_no` 범위 안에서
   파일에 없는 키를 지운다. 그래서 KAM 과 달리 **ps-v1 행을 손으로 지울 필요가 없다** —
   같은 파일을 그대로 다시 적재하면 값이 갱신되고 사라진 키가 정리된다.

   새로 생긴 유형자산 자산군 행(3,699행)도 이 키에 그대로 들어간다. `subject` 는 `String(64)` 이고
   이번 코퍼스의 최장 값이 21자(「토지, 건물, 구축물을 제외한 유형자산」·「토지와 건물, 구축물을
   제외한 유형자산」)라 여유가 크다. 다만 **`subject_key` 정규화가 새 문자열을 받아들여야 한다** —
   원문을 그대로 옮긴 값이라 같은 뜻이 여러 철자로 나온다. 이번 코퍼스의 자산군 어휘는 18종이다:

   | subject | 행 |
   |---|---|
   | `토지` | 1,915 |
   | `토지를 제외한 유형자산` | 950 |
   | `건물` | 457 |
   | `토지와 건물을 제외한 유형자산` | 274 |
   | `토지 및 건물을 제외한 유형자산` | 40 |
   | `기계장치` | 30 |
   | `건물을 제외한 유형자산` · `구축물` | 6 · 6 |
   | `토지와 기계장치를 제외한 유형자산` | 6 |
   | `토지, 건물을 제외한 유형자산` | 3 |
   | `토지을 제외한 유형자산`(**원문 오타**) · `토지와 건물를 제외한 유형자산`(오타) · `토지 및 건물를 제외한 유형자산`(오타) · `토지, 건물, 구축물을 제외한 유형자산` | 2 · 2 · 2 · 2 |

   「토지 X 건물을 제외한 유형자산」 하나만 해도 조사·구두점이 다른 철자가 여섯이고(`와`/`및`/`,`,
   그리고 `을`/`를` 오타와 띄어쓰기 누락), 원문 오타 「토지**을** 제외한」도 2행 있다.

   다음 분기 원문에서 새 철자가 나오는 순간 빈칸이 된다.
